# AI Attribution

## Purpose

Make every Twinmate-generated message distinguishable from a human-authored
message across web, desktop and unmodified native mobile Mattermost clients.

## Requirements

### Requirement: Persistent in-body attribution

Every message Twinmate publishes on behalf of its owner MUST store an
unambiguous, locale-neutral AI-generated marker in the message body, as
well as machine-readable provenance metadata. The marker MUST remain visible
in native mobile clients and when consecutive posts have their headers hidden.

#### Scenario: Message from a developer's local agent

- GIVEN a valid Twinmate agent key
- WHEN the agent publishes a result as its owner
- THEN the resulting Mattermost post begins with the `🤖 Twinmate · AI-generated` label
- AND the post includes machine-readable Twinmate provenance

#### Scenario: Native mobile or grouped messages

- GIVEN a Twinmate-authored message is displayed on a native mobile client
- WHEN the client cannot render Mattermost webapp-plugin components
- THEN the persistent in-body marker still identifies it as AI-generated

### Requirement: Server-verified web badge

On Mattermost web/desktop versions with the post-header extension API
(11.9 and later), Twinmate MUST display a compact, localized AI badge
only after checking server-owned provenance for the specific post. It
MUST NOT treat user-editable post properties as sufficient verification.
On older supported Mattermost versions, the persistent body label remains
the attribution fallback.

#### Scenario: Valid AI post shown in localized web client

- GIVEN the server confirms a post was generated by Twinmate
- WHEN a user views its visible post header on Mattermost 11.9 or later
- THEN the client shows an AI-twin badge localized to the viewer's language

#### Scenario: Forged post properties

- GIVEN a human-authored post with client-supplied `twinmate.generated` metadata
- WHEN a web client requests server provenance for that post
- THEN the server does not verify it as a Twinmate-generated message
- AND the web client does not show the verified AI badge

#### Scenario: Older web client or grouped header

- GIVEN a Twinmate-generated post on Mattermost 11.0–11.8 or a grouped post without a header
- WHEN the post is displayed
- THEN the in-body AI-generated label remains visible

### Requirement: Provenance respects message visibility

The provenance verification endpoint MUST authenticate the viewer and
MUST NOT disclose proof for posts the viewer is not permitted to read.

#### Scenario: Outsider requests provenance

- GIVEN a user is not authorized to access a private conversation
- WHEN they request provenance for a message in that conversation
- THEN the endpoint refuses to disclose whether that protected post was AI-generated
