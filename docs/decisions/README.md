# Architecture decision records

An ADR records a **reviewed decision**, not a brainstorm or vendor promise. Number files sequentially (`0001-...md`). Do not rewrite accepted decisions in place; supersede them with a new ADR that links the earlier one.

Each ADR includes:

- **Status:** proposed, accepted or superseded.
- **Context:** problem and constraints.
- **Alternatives:** at least two plausible options and their tradeoffs.
- **Decision:** explicitly agreed option, or `Pending`.
- **Consequences:** risks, operational cost, testing and rollback.
- **Evidence:** links to dated research and OpenSpec change.
